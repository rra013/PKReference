Part 3. Spring, as this project uses it

Spring's job here is to build the objects and connect them. This part explains each mechanism once, with where the code uses it. If an interviewer points at an annotation, the answer is in this part.

3.1 Beans and dependency injection

A bean is an object that Spring creates and keeps, normally exactly one of each (a singleton). The set of all beans is the application context. Classes don't create their collaborators: they declare them as constructor parameters, and Spring passes them in. That is dependency injection.

@Component
public class EventFetcher {
    public EventFetcher(LimitlessClient client, EventFetchRepository fetches,
                        KafkaTemplate<String, Object> kafka, LimitlessProperties props, Clock clock) { ... }
}

Spring sees one constructor, finds a bean of each parameter's type, and calls it. No @Autowired is needed when a class has a single constructor. (LimitlessClient and SmogonClient have two, one for tests, so the one Spring should use is marked @Autowired.)

Why bother. A class that receives its collaborators can be given fakes. The tests build an EventDiscovery with a mock client, a mock Kafka template and a fake clock, and check exactly which events it asks for, with no network and no broker.

3.3 The annotations on BackendApplication

  • @SpringBootApplication combines three: @Configuration (may hold @Bean methods), @ComponentScan (find annotated classes in this package and below) and @EnableAutoConfiguration (configure whatever libraries are on the classpath from application.yml: the data source, Flyway, the Kafka producer and listener factory, Jackson, Tomcat).
  • @ConfigurationPropertiesScan finds the settings records (next section).
  • @EnableScheduling turns on @Scheduled.

3.4 Settings: @ConfigurationProperties

Three records hold the project's own settings: LimitlessProperties (pkref.limitless), SmogonProperties (pkref.smogon) and ApiAuthProperties (pkref.api). Spring builds each from the matching block of application.yml, converting text to the field's type: 30m to a Duration, M-C,M-B to a List<String>. Kebab-case in YAML (poll-interval) matches camelCase in Java (pollInterval).

In the YAML, ${LIMITLESS_LOOKBACK:7d} means "the environment variable LIMITLESS_LOOKBACK if set, otherwise 7d". Each record's compact constructor fills in defaults and, for ApiAuthProperties, refuses bad values, so a misconfigured server fails at start-up with a clear message.

3.5 Timers: @Scheduled

EventDiscovery.poll() and LadderDiscovery.poll() are called by Spring's scheduler. fixedDelay measures from the end of one run to the start of the next, so a slow run can't overlap itself. The scheduler's thread pool is set to 2 in application.yml so the two polls don't wait for each other.

@ConditionalOnProperty(name = "pkref.limitless.ingest-enabled", ...) on the class means the bean is only created when that setting is true. Tests switch both polls off that way.

3.6 Kafka: KafkaTemplate and @KafkaListener

Producing. KafkaTemplate<String, Object> is auto-configured from spring.kafka.producer. kafka.send(topic, key, value) serializes the value to JSON and returns a future; the project always passes that future to KafkaSends.await, so a failed send throws where it happened instead of being logged and forgotten.

Consuming. A method annotated @KafkaListener(topics = ..., groupId = ...) gets a consumer thread of its own. Spring polls the topic, rebuilds each record's value from JSON into the parameter's type, and calls the method. Returning normally means "done"; throwing means "failed", which hands the record to the error handler. There are five listener methods:

3.7 The web layer

  • @RestController: a bean whose methods handle HTTP requests; return values become JSON.
  • @RequestMapping("/v1") on the class: the path prefix for all its methods.
  • @GetMapping("/formats/{format}/pokemon"), @PostMapping("/token"): the verb and path of one method.
  • @PathVariable: an argument taken from a {...} part of the path. @RequestParam: one taken from the query string, required unless it has required = false or a defaultValue.
  • ResponseEntity<T>: a response whose status and headers the method sets, used here to add Cache-Control.
  • @ExceptionHandler(X.class): a method of the same controller that Spring calls when a handler throws X. The project maps IllegalArgumentException to 400 and NoSuchElementException to 404, so services can signal "bad input" and "not there" with ordinary exceptions.
  • Filters (FilterRegistrationBean): code that runs around every matching request, before any controller. Two here: ApiAuthFilter on /*, first, and ShallowEtagHeaderFilter on /v1/*.
  • @Tag, @Operation, @Parameter, @Schema: springdoc's. They describe the API for Swagger UI and have no effect on behavior.

3.8 The database layer

  • JdbcTemplate (and NamedParameterJdbcTemplate): run SQL with parameters and map rows with a lambda. Used by TeamStore, MetaRepository, CorpusRepository, EventFetchRepository, LadderStore.
  • JPA: @Entity classes mapped to tables by Hibernate, with repositories Spring Data generates from interfaces (UsageCounterRepository). Used only by the original usage counters.
  • @Transactional: the method runs in one database transaction, committed when it returns and rolled back if it throws. On TeamStore.putStandings, putPairings, LadderStore.put and UsageAggregationService.apply. It works through a proxy Spring puts around the bean, so it applies to calls coming from another bean, which all of these are.

3.9 Java features worth being able to explain

  • Records (public record Share(String value, double share) {}): immutable data classes. All wire types, responses, settings and query rows are records. A compact constructor (public LimitlessProperties { ... }) validates or defaults the fields.
  • Text blocks ("""..."""): multi-line strings, used for SQL.
  • var: a local variable whose type the compiler infers.
  • Switch expressions: return switch (result) { case "P1" -> ...; default -> 1; };
  • Streams and lambdas: most of MetaService's counting and sorting.
  • Optional: a return type that says "there may be none" (LadderStore.find).
