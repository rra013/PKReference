Part 10. Running it

10.1 Locally

cd backend
docker compose up -d          # Kafka (9092), Kafka UI (8081), Postgres (5432), all on 127.0.0.1
mvn spring-boot:run           # the server, on 127.0.0.1:8080
curl localhost:8080/v1/formats
open http://localhost:8080/swagger-ui.html
mvn verify                    # every test

On first start Flyway creates the tables, the topics are created, and within seconds discovery starts asking for the last 7 days' events and the ladder discovery fetches the two newest months.

10.3 On a server

docker-compose.server.yml layers on top of the local file: it adds the API as a container built by the Dockerfile (two stages: build with Maven, run on a JRE as a non-root user), sets memory limits and restart policies, and requires a real Postgres password and at least one key hash. Everything still binds to 127.0.0.1; other devices reach the API through Tailscale's HTTPS. scripts/backup.sh dumps Postgres daily; scripts/new-api-key.sh makes a key and its hash.

10.4 Rebuilding the tables from the topics

With the server stopped, reset a consumer group to the start of its topic and start the server again:

docker compose exec kafka /opt/kafka/bin/kafka-consumer-groups.sh --bootstrap-server kafka:19092 \
  --group team-store-standings --reset-offsets --to-earliest --all-topics --execute

The group re-reads every record, and because each write replaces what's there, the tables end up as if they had been filled for the first time with today's code.
